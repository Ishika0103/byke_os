# Plan 02: Hotels (master data + CRUD)

> Status: ✅ Approved and built (2026-11-21)
> Builds on Plan 01 Part A (roles/users). Follows the same layering, envelope, soft-delete and migration rules.
> Room types and rooms come in the next plan; they will hang off `hotels`.

## 1. Goal

Replace the hardcoded demo hotels in the app with real hotels stored in MongoDB, managed through the same kind of list / add / edit / status / delete screens as Users and Roles. The Home hotel picker then loads from the API.

## 2. Data model: `hotels`

```
hotels {
  _id,
  name,                       // "The Byke Brightland Resort"
  code,                       // "BRG"   generated from the name, unique, never changes
  location: { city, state },  // picked from the fixed Indian city list (§3)
  checkInTime,                // "14:00"  24-hour HH:mm
  checkOutTime,               // "11:00"
  isActive, isDeleted,
  createdBy, updatedBy,       // user ids
  createdAt, updatedAt
}
```

| Field          | Rules                                                                                                                                                                                                                                                                                                            |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`         | 2–100 chars, trimmed. Unique (case-insensitive) among non-deleted hotels.                                                                                                                                                                                                                                        |
| `code`         | **Generated by the API** from the name: initials of the main words ("Old Anchor Beach" → `OAB`), or first letter + consonants of a single word ("Brightland" → `BRG`). Words like The / Byke / Hotel / Resort are skipped. If taken, a number is added (`TST2`). Unique among non-deleted hotels, **immutable**. |
| `location`     | `{ city, state }` must be one of the entries in the shared city list.                                                                                                                                                                                                                                            |
| `checkInTime`  | `HH:mm`, 00:00–23:59. Required.                                                                                                                                                                                                                                                                                  |
| `checkOutTime` | `HH:mm`. Required. No ordering rule between the two (check-out is the next day).                                                                                                                                                                                                                                 |

Indexes (one migration): `code_unique` and `name_unique_ci` (both partial on `isDeleted: false`), plus `{ 'location.city': 1 }` for filtering.

## 3. Location list (decided: fixed Indian city list)

- `packages/shared/src/data/indian-cities.ts`: `INDIAN_CITIES: { city, state }[]`, ~200 entries.
  It covers every state/UT capital, major cities, and all cities where Byke operates today
  (Matheran, Mahabaleshwar, Ooty, Nashik, Thane, Ujjain, Indore, Bhopal, Jaipur, Kumbhalgarh, Osian, Junagadh, Surat, Palghar, Kovalam, Gurugram, Bengaluru, Mumbai, Manali, Shimla, Bodhgaya, Prayagraj…).
  Goa is listed as **North Goa** and **South Goa** (state Goa), the way Byke splits it.
- Shared, so the app shows it and the API validates against the same list. No outside service.
- Adding a city later = one line in this file + `npm run build -w @byke-os/shared`.

## 4. API (`apps/api/src/modules/hotels/`)

`hotel.routes.ts → hotel.controller.ts → hotel.service.ts → hotel.model.ts`, mounted behind `authenticate` (permissions are still on hold, same as users/roles).

| Method | Path          | Body / query                                                                              |
| ------ | ------------- | ----------------------------------------------------------------------------------------- |
| GET    | `/hotels`     | `page`, `limit`, `q` (name, code, city), `isActive`, `sort` (`name`, `code`, `createdAt`) |
| POST   | `/hotels`     | `name`, `location`, `checkInTime`, `checkOutTime`, optional `isActive` (default true)     |
| GET    | `/hotels/:id` |                                                                                           |
| PATCH  | `/hotels/:id` | any of `name`, `location`, `checkInTime`, `checkOutTime`, `isActive` (not `code`)         |
| DELETE | `/hotels/:id` | soft delete (`isDeleted: true`)                                                           |

Errors: `CODE_TAKEN` / `NAME_TAKEN` → 409 shown on the field; unknown city → 400 on `location`.
No in-use rule yet (nothing points at hotels). The room-types plan will add "can't delete or deactivate a hotel that has active room types".

Shared (`packages/shared/src/schemas/hotel.ts`): `createHotelSchema`, `updateHotelSchema`, `hotelListQuerySchema`, `Hotel` type, `timeOfDaySchema`.

## 5. App

- **Hotels list** (`/hotels`, reached from Settings → Administration → Hotels): same look as Roles. Header with back + add button, search (name / code / city), rows show the hotel icon, name, `CODE · City, State`, and the green/red Active pill.
- **Add / edit hotel** (`/hotels/new`, `/hotels/[id]`), Save pinned at the bottom:
  - Details: Name, Code (locked after creation).
  - **Location**: a select field that opens a bottom sheet with a **search box** at the top (filters by city or state as you type) and the matching cities below, shown as "Matheran · Maharashtra".
  - **Check-in / Check-out time**: select fields that open a bottom sheet of times every 30 minutes, shown as "2:00 PM". Defaults for a new hotel: 2:00 PM / 11:00 AM.
  - No code field when adding (it's generated); the edit screen shows it read-only.
  - **Status** switch on the add screen too (no confirmation, nothing is saved until Create).
  - Edit only: Status toggle with confirmation (same component as users/roles) and "Delete hotel" with confirmation.
- **Quick add (+)** gets a third option: Add hotel.
- **Home hotel picker** loads active hotels from `GET /hotels?isActive=true&limit=100` instead of the demo list. Selected hotel still lives in memory (default: first hotel). If there are no hotels yet, Home shows an empty state with "Add hotel".
- The Home numbers (occupancy, arrivals…) **stay demo numbers**, still labelled "Demo numbers", generated per hotel until the real modules exist. `features/hotels/data/demo-hotels.ts` is removed.
